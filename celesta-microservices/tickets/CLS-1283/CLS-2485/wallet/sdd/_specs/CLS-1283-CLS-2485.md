# Spec for CLS-1283-CLS-2485

branch: CLS-1283-CLS-2485

Wallet part of the MoveBonusCleanup "remove jobs and handlers". Promotion and job-library parts live in their own repos under the same branch name.

## Summary

Bonuses moved to promotion. The wallet still carries three kinds of leftovers from the migration:

- **`BonusRollbackJob`**, dispatched by `TransactionRollbackListener::notifyPromotion()` on a sportsbook bet rollback. It duplicates `BonusBalanceRestoredJob`, which `RewardAssetClaimedListener` already emits from the same PLAYED→CLAIMED flush. APM on prod-2 shows both in the same trace, Restored first (trace `6aad0961000000007c1f58078b3bac83`, 2026-09-18).
- **Console commands now owned by promotion**: `expire:bonus:offer`, `expire:bonus:validity`, `bonus-model:refresh-state`. All three only print "handled by the Promotion MS. Skipping" since CLS-2847-CLS-2849.
- **`bonus:cancel`**: sets a sub_balance to CANCELED without telling promotion, which leaves the bonus `claimed` there. The product path is the BO cancel, which goes through promotion and back to wallet's `RefundHandler`. Zero runs in 30 days of APM, all envs.

`transaction:adjust-bonus-balance` stays: it adjusts a wallet sub_balance, and an adjustment down to zero already reaches promotion through `BonusBalanceDepletedJob`.

## Preconditions

- celesta-sb-argocd #846 merged (removes the prod-2 CronJobs that still call the two no-op commands). Without it, prod-2 CronJobs fail every minute after this deploy.

## Functional Requirements

- Remove `notifyPromotion()` and the `PostResponseMessageDispatcher` dependency from `TransactionRollbackListener`. The PLAYED→CLAIMED flush in `revertPlayedBonus()` stays.
- Remove the `BonusRollbackJob` routing from `config/packages/messenger.yaml`.
- Delete `ExpireBonusOfferCommand`, `ExpireBonusValidityCommand`, `RefreshBonusModelStateCommand`, `CancelBonusCommand` and their entries in the `CommandSubscriber` list (`config/services.yaml`).
- Delete `BonusManager::CANCEL_WARNING_MESSAGE_TEMPLATE` (only `CancelBonusCommand` used it). `isFreeRoundsCancelable()` stays, `FreeRoundStartedConstraintValidator` uses it.
- Delete the `ops/scripts/*/wallet-{expire-bonus-offer,expire-bonus-validity,bonus-model-set-status}.sh` scripts and drop those choices from `ops/jenkins/wallet-*-cron.jenkinsfile`.
- Update `docs/service-boundary.yaml`: drop `BonusRollbackJob`.
- Require `lancasters/job-library:dev-CLS-1283-CLS-2485` (the branch that deletes the three classes), switched to the tag before merge.

## Acceptance Criteria

From `tickets/CLS-1283/CLS-2485/matrix.md`, signed off 2026-10-16.

1. Given a sportsbook bonus `played` by a bet, when the bet is rolled back, then wallet dispatches exactly one job, `BonusBalanceRestoredJob`, and promotion returns the bonus as `claimed`.
2. `bin/console list` has none of `expire:bonus:offer`, `expire:bonus:validity`, `bonus-model:refresh-state`, `bonus:cancel`, and still has `transaction:adjust-bonus-balance`.
3. BO `POST /player/{p}/bonus/{b}/cancel` still cancels the bonus in promotion and the sub_balance in wallet.
4. No reference to `BonusRollbackJob`, `BonusPlayedJob` or `BonusClaimedJob` left in wallet. `lancasters/job-library` points to `dev-CLS-1283-CLS-2485` during review and to the release tag before merge.
5. All existing tests pass.

Not exercised, by decision: casino rollbacks, sub_balances without `bonusId`, non-played or zero-amount rollbacks (none dispatch anything before or after).

## Possible Edge Cases

- **Orphan sub_balances** (healthcheck 089, ~10 in prod): a rollback on one used to send `BonusRollbackJob` to `promotion-failed`. Now only `BonusBalanceRestoredJob` goes out and promotion logs "Bonus not found". No balance effect.

Restored dispatch is covered by `RewardAssetClaimedListenerTest`.
