## Overview

The Finance transaction report is served by `POST /api/gateway/domain/{domainId}/finance/transaction_reports`
(`TransactionReportController::getTransactionReportsAction`). It reads celesta-statistics
`GET /api/bi/transaction_movement` through `StatisticsClient::getTransactionMovements()` and maps each movement with
`TransactionReportNormalizer::normalize()`. A payout line exposes one request, `withdrawRequestId`. Once several
withdrawal requests are paid in one payout (CLS-4753, CLS-4755), that single ID is only the lead request.

Sibling CLS-4754 defines the statistics contract: every movement carries `withdraw_request_ids`, a list of integers
or `null`. This sub-task adds that list to each report line as `withdrawRequestIds`, next to the single ID, and
documents it in OpenAPI. The front reads it in CLS-4757. The single ID is removed later, in CLS-4758.

## Architecture & Design

- One response field is added, and nothing else changes: no form, filter, client, controller or count-endpoint
  change. Data flow: statistics `withdraw_request_ids` → `TransactionReportNormalizer::normalize()` →
  `withdrawRequestIds` on each element of the response array.
- Name and shape follow `_rules/general/api-guidelines.md`: camelCase, and an integer ID list is named with the
  `Ids` suffix, as in `contentTagIds` (`ContentBlockType`) and `playerIds` (`Segment\FilterType`). The OpenAPI
  property mirrors `contentTagIds`: an array of integers, `nullable: true`.
- The value is passed through as statistics returns it: same order (ascending, lead included), no casting, no
  re-sorting. Every other field of this normalizer is mapped the same way.
- The key is read with `?? null`, like `fee`, `psp` and `mid` in the same method. If statistics serves movements
  without the key (deploy window or rollback), the line still renders, with `withdrawRequestIds: null`.
- "No request" is `null`, the same as `withdrawRequestId` and `rewarding` on lines with nothing to show.
- `withdrawRequestId` stays unchanged: an integer or `null`, the lead request.
- No choice here lacks a precedent in the existing code.

Value per line:

| Line | `withdrawRequestId` | `withdrawRequestIds` |
|---|---|---|
| `withdraw`, combined payout | `4290150` | `[4290150, 4292746, 4301966]` |
| `withdraw`, single payout or payout synced before the change | `557795` | `[557795]` |
| `withdraw` with no request ID | `null` | `null` |
| `deposit`, `deposit_first`, `deposit_second`, `refund`, `adjustment` | `null` | `null` |
| statistics response without `withdraw_request_ids` | as today | `null` |

## Edge Cases & Error Handling

- **Statistics without the key** (CLS-4754 not deployed yet, or rolled back): `?? null` returns
  `withdrawRequestIds: null`, and the line and the request still succeed. This repository can deploy before or
  after statistics without a failure. The front (CLS-4757) reads only `withdrawRequestIds`, so during a statistics
  rollback payout lines show no request ID until statistics is redeployed.
- **Combined payout whose list statistics returns in a given order:** passed through. The backoffice does not
  re-sort, deduplicate or check that the list contains `withdrawRequestId`.
- **Payout synced before the change:** statistics applies the single-ID fallback when it reads, so the line gets
  `[withdrawRequestId]`. The backoffice does nothing for it.
- **`withdraw_request` and `initial_balance` movements:** statistics excludes them from this list by default
  (`TransactionMovementRepository`, `notTypes`), and the backoffice never sends `notTypes`. Their `null` list in
  the contract never reaches this endpoint.
- **Count endpoint, filters and sorting:** unchanged. No filter or sort by request ID is added.

## Decisions

- **What does `withdrawRequestIds` hold on a line that pays no withdrawal request?** `null`, passed through from

  `withdraw_request_ids ?? null`, as `fee`, `psp` and `mid` are read; statistics owns the single-ID fallback.
  Decided by Lucas.
- **Proteus scenario or statistics mock change?** Neither: the controller and normalizer tests cover a field passed
  through with `?? null`. Decided by Lucas.
