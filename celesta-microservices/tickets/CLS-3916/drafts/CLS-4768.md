# CLS-4768 — {C} [job-library] Add the promotion source type to UserActivityJob

Sub-task: https://celesta.atlassian.net/browse/CLS-4768 · Parent: https://celesta.atlassian.net/browse/CLS-3916 · Repository: celesta-job-library

## Overview

`JobLibrary\Job\Activity\UserActivityJob` declares who caused an activity as a `SOURCE_TYPE_*` constant, listed in `UserActivityJob::SOURCE_TYPES` (`player`, `system`, `application`, `company`, `user`, `seon`, `scenario`, `fraud`), and the causing entity's id in `sourceUserId`. None names a promotion. [CLS-3916](https://celesta.atlassian.net/browse/CLS-3916) has promotions create gifts on rewarding, and requires exactly one `gift_offered` activity per gift, attributed to the promotion.

This sub-task adds the source type `promotion` and ships it in a release that celesta-promotion ([CLS-4772](https://celesta.atlassian.net/browse/CLS-4772)) uses to send that activity and celesta-backoffice ([CLS-4775](https://celesta.atlassian.net/browse/CLS-4775)) uses to render and filter it.

## Architecture & Design

- **The source type.** `UserActivityJob::SOURCE_TYPE_PROMOTION = 'promotion'`, listed in `SOURCE_TYPES`. job-library does not require `lancasters/constants`, so the value is a literal, like every other source type; the test pins it. celesta-activity ([CLS-4769](https://celesta.atlassian.net/browse/CLS-4769)) declares the same string on its side.
- **What `sourceUserId` carries for it.** The promotion configuration id (`promotion_configuration.id` in celesta-promotion), mirroring `SOURCE_TYPE_SCENARIO`, which carries the scenario id: crm's `UserActivityDispatcher` sends the request source id with `SOURCE_TYPE_SCENARIO`. The configuration is what the backoffice names as the gift's creator ("the promotion, name and ID", per the parent), and the id lets the activity API select one promotion's entries with `filter[sourceTypes]=promotion` and `filter[sourceIds]`. The player's promotion instance (`promotion.id`), if a consumer needs it, goes in `additionalData`, which this repository does not shape.
- **Who writes it.** celesta-promotion ([CLS-4772](https://celesta.atlassian.net/browse/CLS-4772)), when a rewarded instance creates a gift. Today `gift_offered` is sent only by celesta-backoffice (`UserActivityJobManager::dispatchGiftOfferJob`, `SOURCE_TYPE_USER`).
- **What does not change.** No new field, class or event; `sourceType` is already a free string on the wire, so the serialized shape of `UserActivityJob` is unchanged. The change is additive.

## Implementation Tasks

1. In `src/JobLibrary/Job/Activity/UserActivityJob.php`, add `public const SOURCE_TYPE_PROMOTION = 'promotion';` directly after `SOURCE_TYPE_FRAUD`.
2. In the same file, append `self::SOURCE_TYPE_PROMOTION,` as the last entry of `UserActivityJob::SOURCE_TYPES`, after `self::SOURCE_TYPE_FRAUD`, adding the trailing comma the `SOURCE_TYPE_FRAUD` line lacks today.
3. In `tests/JobLibrary/Job/Activity/UserActivityJobTest.php`, add `testPromotionSourceType(): void` after `testGiftOfferedEvent()`, asserting `assertSame('promotion', UserActivityJob::SOURCE_TYPE_PROMOTION)` and `assertContains(UserActivityJob::SOURCE_TYPE_PROMOTION, UserActivityJob::SOURCE_TYPES)`.
4. Run the command in Testing Strategy and fix what the change broke.

- `UserActivityJobTest::testPromotionSourceType` — pins the wire string and its membership in `SOURCE_TYPES`, mirroring `testGiftOfferedEvent` and `testUpdatePlayerTagEvent`; a rename fails CI here before it reaches celesta-promotion, celesta-activity and celesta-backoffice, which match on the string.

- Command, from the repository root (the repository has no container; `CLAUDE.md` gives the host command, which `.claude/settings.json` allows): `composer install` (needs access to repo.packagist.com/lancastersolutions), then `vendor/bin/phpunit tests/JobLibrary/Job/Activity/UserActivityJobTest.php`, then `vendor/bin/phpunit` for the full suite.

## Proteus tests

None. celesta-job-library is a library with no running service or API, so no Proteus scenario observes it. The parent's criterion it underpins, "Exactly one `gift_offered` activity event per gift, attributed to the promotion; no `gift_claimed` event", is observed through the services that send, store and render the event: the plans of [CLS-4772](https://celesta.atlassian.net/browse/CLS-4772) (promotion), [CLS-4769](https://celesta.atlassian.net/browse/CLS-4769) (activity) and [CLS-4775](https://celesta.atlassian.net/browse/CLS-4775) (backoffice).

## Edge Cases & Error Handling

- **Consumers on an older job-library.** No PHP service rebuilds `UserActivityJob` from `QUEUE_ACTIVITY`; celesta-activity (Go) reads `source_type` as a string. A service that does not bump is unaffected unless it validates against `SOURCE_TYPES`.
- **Validation against `SOURCE_TYPES`.** celesta-backoffice builds `filter[sourceTypes]` of `POST /api/gateway/logs` as a `ChoiceType` on `UserActivityJob::SOURCE_TYPES` (`GatewayBundle/Form/Type/Log/FilterType.php`), and uses it as the `LogFilter.sourceTypes` OpenAPI enum. Until it bumps job-library, a request filtering on `promotion` is rejected as a validation error; requests that do not filter on source type are unaffected.
- **Activity before CLS-4769.** celesta-activity does not validate the source type on ingestion, so a `promotion` row is stored as sent; only `filter[sourceTypes]=promotion` on its API is refused until `AllSourceTypes` lists it.
- **The string is permanent.** `promotion` is stored on activity rows; renaming it later breaks the source-type filter for past rows.
- **Release number.** `release.yml` creates the next minor on each merge to `master` (latest today `v3.149`); a pull request merged first takes that number, so the version to require is the one actually created.

## Acceptance criteria

- `UserActivityJob::SOURCE_TYPE_PROMOTION === 'promotion'`.
- `UserActivityJob::SOURCE_TYPES` contains `UserActivityJob::SOURCE_TYPE_PROMOTION`, and its eight existing entries are unchanged.
- A `UserActivityJob` with `sourceType` `promotion` and an integer `sourceUserId` serializes and deserializes as any other source type; no existing constant, field or serialized key changes, and the existing `UserActivityJobTest` cases pass unmodified.
