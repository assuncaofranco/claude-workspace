# CLS-3540 — How to test (cms #281, coverage refactor)

**Feature:** content block filter, translation mapper and T&C locales rewritten for 100% coverage; behaviour unchanged except a wrongly typed filter body now gives 400 instead of 500.

## Setup
- Branch `CLS-3540` deployed on cms in pp1 (BO and gateway on master).
- `./run-pp1.sh` runs everything in order; `PP=2 ./run-pp1.sh` for preprod-2. Credentials come from the vault.
- Edit `gen.py`, not the JSON; `run-pp1.sh` regenerates it.

## Steps
1. GW player token (player id from the token), BO token, domain languages, the player's segments.
2. BO creates tags T and T2 and six blocks: `any`, `user`, `segin` (player's segment), `segout` (segment 999999999), `country`, `other` (T2 only); enables them.
3. BO PUTs `user` with v2 content and tags `[T]`; GET shows v2 in every language and only T.
4. GW player by tag name, by tag id, and in the second language: sees `any`, `user`, `segin`; not `segout`, `country`, `other`; content in the asked language.
5. GW player by T2: only `other`.
6. GW visitor (application token): sees `any` and `country` only.
7. BO T&C draft create and update: content for every domain language. Never publish.
8. BO deletes the blocks and tags.

## Variables

| Variable | Example | What it is |
|---|---|---|
| `BO_baseUrl` / `baseUrl` | pp1 backend-api / gateway | entry points, from the vault |
| `domainId` | `56` | domain under test |

Captured at runtime: `runTag`, tokens, `playerId`, `langs`, `lang1`, `lang2`, `segIn`, `tagT`, `tagT2`, `cb_*`, `tcId`.

## Notes
- All PO-runnable: BO and GW only.
- Wrong type body → 400 is not reachable through the gateway (its form validates types first). Covered by the PR's `ContentBlockControllerTest` (86 green locally on 2026-11-03).
- No second language on the domain skips the lang2 read; a player with no segment skips `segin`. Both log why.
- The T&C draft has no delete route and stays in the list, named with `runTag`.
- The user activity job of the T&C draft is read through BO `POST /api/gateway/logs` with `filter.event` `create_terms_and_conditions`/`update_terms_and_conditions` and `domainIds`: create carries `terms_and_conditions_id` and `domain_id`, update also `terms_and_conditions_history_ids`.
- BO `GET terms_and_conditions` gives 403 for the vault user in pp1 (missing BO permission, not cms). The step is informative only.
- pp1 run before the deploy, 2026-11-03: 35 requests, 93 assertions, 0 failures (folders 0-3 and 5).
- pp1 run after the deploy (image `CLS-3540-2780730`), 2026-11-03: 38 requests, 100 assertions, only the list 403; folders 0-3 and 5 rerun on the new pod, 93/93. T&C draft 11 created after the pod start; activity logged with the same shape as before.
