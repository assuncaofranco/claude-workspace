# CLS-3888 — T&C language added to domain after creation

**Feature:** a language added to the domain after a T&C was created can be saved on it, and publish refuses a T&C missing a domain language.

## Setup

- Import `CLS-3888.postman_collection.json`, no environment.
- Stack up: backoffice, crm, cms.
- Fill the `BO_*` credentials in the runner environment (dev values in the vault).
- Run the whole collection in order; two requests wait 61s for the cms domain cache.

## Steps

1. BO token.
2. Set domain secondary languages without `newLanguage`.
3. Create and fill T&C A.
4. Create and fill T&C B.
5. Add `newLanguage` to the domain.
6. Publish B without saving the new language → 400.
7. Save A with the new language → content kept.
8. Read A → content persisted.
9. Publish A → 200.
10. Remove `newLanguage` from the domain.

## Variables

| Variable | Example | What it is |
|---|---|---|
| `BO_baseUrl` | `http://localhost:84` | Backoffice |
| `domainId` | `2` | Domain under test |
| `baseSecondaryLanguages` | `["en","de","en-AU"]` | Domain secondary languages before the test |
| `newLanguage` | `es` | Language added after T&C creation |

Captured at runtime: `BO_access_token`, `tncSavedId`, `tncNotSavedId`.

## Notes

- PO-runnable: everything goes through the backoffice. In preprod, set `domainId` and `baseSecondaryLanguages` to the target domain's real values, or step 10 overwrites them.
- Step 9 publishes A, which unpublishes the domain's current T&C.
- Before the fix: steps 6, 7 and 8 fail (publish returns 200, the new language text is dropped).
