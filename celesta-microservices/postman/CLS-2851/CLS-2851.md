# CLS-2851 Relax free spins cancel

**Feature:** o webhook Relax `notifyFreespinsCancel` cancela o bônus sempre no promotion, sem flag.

## Setup
- `./run.sh` (local) ou `./run-pp1.sh --env-var playerId=282570` (pp1); credenciais vêm do vault
- pp1: jogo `55672` (Money Train 3), gateway `41`, studio `562`, domínio `56`
- game na branch `CLS-2851`, promotion e wallet em master
- ordem fixa: as pastas 1 → 4 numa invocação só

## Steps
1. BO: cria reward configuration free_rounds do jogo Relax e habilita
2. BO: oferece dois bônus (A e B)
3. GW: launch real do jogo Relax, captura `cashiertoken`
4. GW: lista bônus e faz o claim só do A (cria o grant no game)
5. Relax: cancel do A → 200
6. Relax: repete o cancel do A → 403
7. Relax: cancel do B (sem grant), promocode desconhecido, token inválido → erros
8. GW: A `canceled`, B `offered`

## Variables
| Variable | Example | What it is |
|---|---|---|
| `gameId` | `6` | jogo Relax com `free_rounds_allowed` |
| `externalGameId` | `421` | `gameref` do webhook |
| `gameGatewayId` / `gameStudioId` | `4` / `4` | gateway e studio do mesmo jogo |
| `playerId` | `1` | dono do token do GW |
| `gameUrl` | `http://localhost:89` | host do game, onde o Relax bate |

Capturados: `runTag`, tokens, `rcFrId`, `bonusA`, `bonusB`, `gwA`, `gwB`, `cashiertoken`.

## Notes
- A pasta 3 é callback de provedor, chamada direto no game. Em preprod só roda se o host público do webhook Relax for alcançável.
- Conferir no banco depois do passo 5: `bonus.status`, `sub_balance.status` (por `bonus_id`) e `free_round_grant.status` todos `canceled`.
- Repetição dá 403 `DAILY_TIME_LIMIT`: `RelaxProvider::mapWalletToRelaxError` manda qualquer 4xx do promotion para esse código. Comportamento antigo, não é do PR.
- O Relax não existe local: o grant fica `pending` e o launch acontece antes do claim de propósito.
