## Estado em 2026-09-22 fim do dia — quase tudo fechado

A frase "nada foi corrigido nos PRs ainda" acima **venceu**. Depois dela vieram duas rodadas de
correção e um terceiro passe de review. Resumo do que mudou:

**Corrigido e pushado:** validator por `match` de tipo (16 testes, um por tipo); `fromEntity` via
empilhamento das branches (2980 ← 2978 ← 2979 nos dois repos); nome duplicado → 400 no campo;
`enabled: null` → 400; erros de booleano reportados todos de uma vez; `?? true` → omissão de chave;
`options` vazio como `{}`; OpenAPI POST 201 + `required`; `max_duration = 60s` nas duas chamadas de

validator; matriz movida para dentro do spec do 2980; três testes funcionais pelo kernel nos endpoints
de escrita do BO.

**Recusado, com motivo registrado no plano:**

- `catch (Throwable)` → `catch (\Exception)` no validator. Testado ao vivo: um valor de tipo errado
  dentro de `options` (objeto aninhado onde o client quer string) dá `TypeError`, que **não** é
  `Exception` — estreitar viraria 500 num input que o editor de JSON cru do CLS-2981 produz fácil. Bug
  nosso e input ruim chegam os dois como `TypeError`, nenhum catch separa; quem separa é o log.
- Pingar a AleaPlay com `{ __typename }`. É o único tipo que não toca a rede, e por isso é o caminho
  feliz dos testes, da coleção e do plano de preprod. Além disso introspecção costuma responder antes
  de autenticar, então poderia não validar nada. Se quiserem, é ticket separado.
- Fechar a corrida de nome duplicado (dois creates simultâneos ainda dão 500 no flush). O índice único
  é a garantia real e está no plano; não vale o `catch` para um cenário de dois operadores no mesmo
  segundo.

**Continua fora do nosso alcance:** a captura de body no nginx do game (ticket de DevOps). Vale para
preprod também — o overlay `cel-preprod-1` não patcheia o nginx e o Datadog de preprod roda com
`logs_container_collect_all = true`. Por isso a coleção usa valores falsos em `options`.
