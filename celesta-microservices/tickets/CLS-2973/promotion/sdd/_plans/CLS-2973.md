# Plan: CLS-2973

spec: [_specs/CLS-2973.md](../_specs/CLS-2973.md)
branch: CLS-2973 (from `master` @ `c28ffe614`)

## Overview

Delete the segment-currency comparison from the promotion configuration validator, the constraint
option it raises, and the tests that exist only to assert it. `validateDomainId()` and the
internal-error path stay exactly as they are.

Pure removal — no behaviour is added. The one new test exists to pin the post-CLS-2053 shape of
the segment response so the removal cannot silently regress.

## Implementation Tasks

### 1. Validator

`SegmentConstraintValidator::validate()` keeps its guards (`$constraint` type, `$value` type,
`$segmentIds` is an array, `$domainId` is set) and its `try/catch`.

Remove:
- the `$currency` resolution line (`$submittedData['currency'] ?? $value->getCurrency() ?? null`)
- the `if ($currency)` block calling `validateSegmentCurrencies()`
- the `validateSegmentCurrencies()` method in full

The `try` body becomes a single `validateDomainId()` call. `$submittedData` is still needed for
`$segmentIds`, so it stays.

### 2. Constraint

Remove the `messageInvalidCurrency` property from `SegmentConstraint`. `messageInvalidSegments`
stays. Nothing else in `src/` or `tests/` references the removed property — verified by grep
before and to be re-verified after.

### 3. Unit tests

Delete these ten, each of which exists only to exercise the currency comparison:

| Test | Why it goes |
|---|---|
| `it_fails_when_segment_currency_differs_from_promotion_configuration_one` | asserts the removed violation |
| `it_fails_when_a_selected_segment_currency_differs` | same |
| `it_fails_when_multiple_selected_segments_have_different_currency_than_requested` | same |
| `it_fails_when_payload_currency_and_value_currency_mismatch_segment_currency` | same |
| `it_passes_when_all_selected_segments_have_matching_currency` | asserts the removed rule's happy side |
| `it_passes_when_selected_segments_are_subset_and_all_match_currency` | would duplicate `it_passes_when_all_segment_ids_belong_to_domain` |
| `it_does_not_fail_for_non_selected_segment_currency_diff` | scopes a comparison that no longer runs |
| `it_uses_value_currency_if_payload_currency_is_missing` | covers the deleted `??` resolution |
| `it_fails_if_neither_payload_nor_value_currency_present` | same (name already contradicts its own `assertNoViolation`) |
| `it_prefers_payload_currency_over_value_currency` | same |

Adjust these two:

- `it_fails_when_both_domain_and_currency_mismatch_on_promotion_configuration_and_segment` —
  drop the `messageInvalidCurrency` assertion and rename to
  `it_fails_on_domain_mismatch_even_when_currencies_differ_too`, keeping the differing currencies
  in the fixture on purpose: it proves the domain rule still fires while currency is ignored.
- `it_fails_when_segment_ids_do_not_belong_to_domain` and
  `it_fails_when_segment_service_throws_exception` — drop `'currency' => 'EUR'` from the payloads
  and the `currency` keys from their segment fixtures, so nothing points at a concept the
  validator no longer has.

Add two:

- `it_passes_when_segments_carry_no_currency_key` — segments returned as
  `['id' => 1, 'name' => 'Segment 1']`, payload carrying `'currency' => 'EUR'`,
  `assertNoViolation()`. Matrix cell 6, and the post-CLS-2053 shape of the segment response.
- `it_passes_when_segment_currency_differs_from_the_configuration_one` — the exact fixture that
  used to violate, now asserting no violation. Matrix cell 5: the old rule is not merely
  unreachable, it is inverted.

Both new tests go at the end of the file, and the surviving ones keep their original order, so the
diff shows the removals rather than a wholesale rewrite.

Result: 17 tests become 9 — matrix cells 1, 2, 4, 5, 6, 7 and 8, with cell 7 covered twice (plain,
and alongside differing currencies). Cell 3 stays untested, as it was before this ticket.

### 4. Acceptance test

`features/standard/configuration/creation/bo_user_creates_promotion_configuration.feature`
(around line 312) holds *"Backoffice user tries to create promotion configuration with segment
currency not equals configuration one"*, which asserts the removed message verbatim.

Rather than delete it, invert it: **same fixture, opposite outcome**. The segment keeps its
`currency | EUR` column against the `CAD` configuration, and the scenario now ends in *"the
promotion configuration should be created with the specified details"*. Renamed to *"Backoffice
user creates a promotion configuration with a segment of another currency"*.

Keeping the `EUR` value is the point: the step forwards the table straight to the mock, so
dropping the column would mock a segment with no currency at all and the scenario would prove
absence of the key rather than divergence of the value — which is cell 6, already covered by a
unit test, not cell 5. Caught in review.

It needs the tier aggregator and limit rows the other creation scenarios carry, since it now has
to survive the whole creation path rather than fail early on validation.

No other scenario asserts the message — verified by grep for the string across `features/`.

### 5. Out of scope, stated so it is not mistaken for an oversight

The `currency` column passed to `Given domain :domainId has the following segments:` in 38
feature files. The step hands the table straight to the mock without reading the column, so it is
inert. Cleaning it belongs with CLS-2053 or a follow-up, not in this diff.

### Result (2026-09-24)

- phpunit: **OK (1591 tests, 3312 assertions)**
- behat: **980 scenarios (980 passed), 7149 steps (7149 passed)**
- grep: no match in `src`, `tests` or `features`
- phpinsights on the two changed source files reports three findings, all pre-existing and none
  on a line this ticket wrote: the `$value` parameter of `validate()` (signature inherited from
  Symfony's `ConstraintValidator`), the missing `@param` annotations on `validateDomainId()`, and
  `messageInvalidSegments` being a public property (the Symfony `Constraint` convention). Left
  alone — out of scope.

Note: `make lint` only analyses files in `git diff origin/master...HEAD`, so it prints nothing
until the branch has a commit. The two files were linted directly instead.

Postman collection in `sdd/_how_to_test/CLS-2973/`, driving the backoffice entry point only.
Newman on local dev: 5 requests, 15 assertions, 0 failures. It covers cells 5 and 7 of the matrix
end to end, and proves the change discriminates — reverting the two source files and replaying
step 3 brings back the `400` with the removed message.

## Edge Cases & Error Handling

- **Segment response without `currency`** — covered by the new unit test.
- **Segment response with `currency`** — covered by the surviving domain tests, whose fixtures
  still carry the key in one case on purpose.
- **Configuration with no currency** — the removed code only ran under `if ($currency)`, so this
  path is unchanged and needs no new coverage.
- **Segment service failure** — untouched; the existing test stays.
