# CLS-2973 — how to test

**Feature:** a promotion configuration can be saved with segments of another currency, while a
segment outside its domain is still rejected.

## Setup

- Import `CLS-2973.postman_collection.json`. Run with **No environment** — the collection carries
  its own dev defaults.
- Credentials are empty in the file on purpose. Pass them at run time from
  `~/.claude-secrets/celesta-dev.md`: `BO_oauth_client_id`, `BO_oauth_client_secret`,
  `BO_username`, `BO_password`.
- Containers needed: `backoffice`, `promotion`, `segment`.
- Order-dependent — run the whole collection in one invocation.

## Steps

1. Fetch the backoffice token.
2. Read segment `{{segmentIdA}}` and confirm its currency is not the configuration's.
3. Create a `{{configurationCurrency}}` configuration selecting segments A and B.
4. Read the configuration back.
5. Create another one with a segment outside the domain and expect the domain violation.

## Variables

| Variable | Example | What it is |
|---|---|---|
| `BO_baseUrl` | `http://localhost:84` | Backoffice entry point |
| `domainId` | `1` | Domain under test |
| `segmentIdA` / `segmentIdB` | `1` / `2` | Two segments of the domain, in a currency other than `configurationCurrency` |
| `foreignSegmentId` | `999` | An id that belongs to no segment of the domain |
| `configurationCurrency` | `CAD` | Configuration currency, deliberately different from the segments' |
| `BO_oauth_client_id` … `BO_password` | — | From the vault, at run time |

Captured at run time: `BO_access_token`, `promotionConfigurationId`, and the `startDate` /
`endDate` / `configurationName` the pre-request scripts generate.

## Notes

- Fully PO-runnable. Backoffice entry point only, no DEV-only call, no guard header.
- Expected: step 3 returns `200`, step 5 returns `400` with *"One or more segments do not belong
  to the domain."*
- Before the change, step 3 returned `400` with *"All selected segments must have the same
  currency as the promotion configuration."* — verified by reverting the two source files and
  replaying the same request.
- Newman run 2026-09-24 on local dev: 5 requests, 15 assertions, 0 failures.
- Step 2 passes either way by design: it asserts a differing currency while the segment still
  exposes one, and skips the comparison once CLS-2053 removes it.
- **The backoffice UI cannot reach this path yet.** The segment dropdown fetches with
  `filter: { currencies: [currency] }` and is disabled until a currency is picked —
  `src/store/reducers/bonusModel.js:547` and
  `src/components/page-components/bonuses/formFields/BonusSegments.js:36` in
  `celesta-backoffice-front`. Until that filter goes, the new behaviour is reachable by API only.
- Each run leaves one extra promotion configuration in the dev database, named
  `CLS-2973 cross currency <timestamp>`.
