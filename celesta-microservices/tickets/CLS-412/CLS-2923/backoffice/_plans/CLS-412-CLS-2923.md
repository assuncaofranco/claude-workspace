# CLS-412-CLS-2923: Plan

## Root cause

The bonus list is not a proxy. `BonusController::getBonuses()` fetches promotion's rows and hands each
one to `BonusNormalizer::normalize()`, which builds a fresh array from a fixed list of keys. A field
promotion adds is dropped unless it is named there.

The list was written before any bonus had an origin worth showing, so it never carried one.
`sourceUserId` has existed on promotion's `bonus` table and in its payload since long before this epic
and is still absent here, which is why the gap only surfaced when CLS-412 asked for the scenario to be
visible. Adding `sourceScenarioId` to promotion alone would have changed nothing on the screen.

## Change

`src/GatewayBundle/Normalizer/Promotion/BonusNormalizer.php`:

- `normalize()` carries `sourceUserId` and `sourceScenarioId` from the promotion row, each defaulting
  to `null`.
- `PromotionBonusNormalized` gains the two properties, both nullable integers.

`sourceUserId` is added although it is not new. The alternative, shipping only the scenario half, gives
the front an origin column that can name a scenario and never an operator — worse than no column, since
every manual offer would read as having no source. One line, and it makes the pair legible.

Promotion refuses a request that carries both sources (`AMBIGUOUS_OFFER_SOURCE`, 400), so the backoffice
needs no rule of its own about which one wins: at most one is ever set.

## Verification

- `BonusNormalizerTest` — three cases: a scenario-offered bonus, a back-office-offered bonus, and a
  promotion payload carrying neither key, which must yield `null` for both rather than a notice.
- `BonusControllerTest::testGetBonusesAction` compares the whole response array, so the expectation
  carries the two new keys. That test is the one that proves the fields survive the controller, not
  only the normalizer.
- Full suite: 3085 tests, one failure, `ConstantControllerTest::testGetConstantsAction`, which is the
  known breakage from a new constant in celesta-constants and fails on master the same way.
- `make lint` exits 0.

## Not in this ticket

The front's bonus list has no origin column. Until it does, the epic's criterion is served by the API
and not by the screen.
