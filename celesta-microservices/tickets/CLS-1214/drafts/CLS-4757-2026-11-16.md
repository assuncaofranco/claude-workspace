# CLS-4757 — {F} [backoffice-front] Show every combined request ID on report payout lines

Sub-task: https://celesta.atlassian.net/browse/CLS-4757 · Parent: https://celesta.atlassian.net/browse/CLS-1214 · Repository: celesta-backoffice-front

## Overview

The transaction report (Finance) shows, in the WDR ID column of each line and in the WDR ID field of the side panel, one link `#<id>` built from `withdrawRequestId`. A click dispatches `getWithdrawalRequest` and navigates, through `getWithdrawalRequestPath`, to the request on the page that lists its status. The same inline code sits twice, in `TransactionReportListItem` and in `SidePanelInfoCards`.

CLS-1214 combines several withdrawal requests into one payout, and the payout line must show every request it paid. CLS-4756 adds `withdrawRequestIds` to every line served by `POST /api/gateway/domain/{domainId}/finance/transaction_reports`. This sub-task makes the front read that list only and render one link per ID, in one component shared by the row and the side panel. CLS-4758 then removes `withdrawRequestId` from the backoffice, which this front no longer reads.

## Architecture & Design

**Contract consumed (CLS-4756).** Each report line carries `withdrawRequestIds`, a list of integers or `null`:

| Line | `withdrawRequestIds` |
|---|---|
| combined payout | every request ID ascending, lead included, e.g. `[4290150, 4292746, 4301966]` |
| single payout, or payout synced before the change | `[withdrawRequestId]` |
| deposit, refund, adjustment, initial balance | `null` |
| statistics does not serve the key yet (deploy window, rollback) | `null` |
| `withdraw_request` movement (only when a caller asks for that type) | `[its own id]` |

A non-null list always has at least one ID. `withdrawRequestId` stays in the response until CLS-4758.

**Components affected**

- `src/components/page-components/transaction-report/WithdrawRequestLinks.js` (new). Takes `ids` and `domainId`. For each ID, in the order received, it renders a celesta-ui `Link` (`as="button"`) with the text `#<id>`, separated by `", "`. A click does what the two call sites do today: it dispatches `getWithdrawalRequest(domainId, id, { onSuccess })`, and `onSuccess` pushes `getWithdrawalRequestPath(domainType, domainSlug, id, withdrawRequest.status)`. The separator and key pattern mirrors the promotion links in `crm/players/player/sportsbook/PlayerBetListItem.sportsbook.js`: a `React.Fragment` keyed by the ID, with `", "` before every item but the first.
- `TransactionReportListItem.js`, the WDR ID `TableValue`, and `SidePanelInfoCards.js`, the `transaction_report.additional_information.wdrId` `InfoCardField`, both render `WithdrawRequestLinks`.
- `TransactionReportTable.js`: unchanged. Its column head keeps `transaction_report.column.wdr_id`.

**Key decisions**

- **The front reads `withdrawRequestIds` only, with no fallback to `withdrawRequestId`.** After this change no source file reads the single field, so CLS-4758 can remove it without touching this repository.
- **The empty case is guarded at the call site.** `TableValue` shows its empty value only when `value` is falsy, and `InfoCardField` adds `null-value` only when `value` is falsy. A rendered component is never falsy, so both call sites pass `withdrawRequestIds?.length ? <WithdrawRequestLinks … /> : null`. This keeps today's `-` for lines without a request; today's `movement.withdrawRequestId && (…)` guards the same way.
- **`domainId` is a prop, not a store read inside the component.** The row already receives `domainId` from `TransactionReportTable`, and the side panel already selects it from `state.global`. Rows are `React.memo`; a selector in each row would subscribe every row to the store.
- **No column width change.** A celesta-ui table cell with no size modifier has no `max-width` and does not wrap (`Table.module.scss`), so three IDs widen the WDR ID column instead of being cut. `InfoCardField` values wrap in the side panel.
- **No client-side sorting.** IDs are rendered in the order the backoffice serves them, which is ascending.

## Edge Cases & Error Handling

- **`withdrawRequestIds` is `null`** (deposit, refund, adjustment, initial balance, statistics not serving the key): the column shows the table's empty value and the side panel field shows its null value, as today when `withdrawRequestId` is `null`.
- **`withdrawRequestIds` is absent** (a backoffice without CLS-4756, after a rollback): handled the same as `null`. Payout lines show `-` until the backoffice serves the key again. No fallback to `withdrawRequestId` (see Decisions).
- **Empty list `[]`:** the contract excludes it. The `?.length` guard treats it as `null`.
- **One ID:** `#<id>`, one link, no separator, as today.
- **Duplicate IDs:** the contract serves distinct IDs. The fragment key is the ID.
- **Clicking one ID of a combined payout:** fetches that request only and navigates by its own status. A failed fetch does nothing, as today (`getWithdrawalRequest` is called without `onError`).
- **Player Payments tab:** it calls the same endpoint (`fetchPlayerPayments`) but renders no request ID. Not touched.

## Acceptance criteria

Narrowed from CLS-1214 ("In the transaction report, a combined payout shows the IDs of all the requests it paid"):

| Line served | Report row, WDR ID column | Side panel, WDR ID field |
|---|---|---|
| `withdrawRequestIds: [4290150, 4292746, 4301966]` | `#4290150, #4292746, #4301966`, three links | same |
| `withdrawRequestIds: [555]` | `#555`, one link, as today | same |
| `withdrawRequestIds: null`, or key absent | empty value `-` | null value |
| `withdrawRequestId: 555` without `withdrawRequestIds` | empty value `-` | null value |

- Each link fetches its own request and navigates to `getWithdrawalRequestPath(domainType, domainSlug, <that id>, <its status>)`.
- No file under `src/` other than `src/translations/` contains the string `withdrawRequestId` except as part of `withdrawRequestIds`.
- `npm run test`, `npm run lint` and `npm run typecheck` pass.

## Decisions

- **Does the front fall back to `withdrawRequestId` when `withdrawRequestIds` is missing?** No. The front reads only `withdrawRequestIds`, so CLS-4758 can remove the single field. Decided by Lucas.
- **One component for the row and the side panel, or two inline renderings?** One shared component, `WithdrawRequestLinks`, used by `TransactionReportListItem` and `SidePanelInfoCards`. Decided by Lucas.
- **Do the translation texts change?** No translation text changes. Decided by Lucas.
- **What happens to the unreferenced key `transaction_report.column.withdrawRequestId`?** It is left as is. Decided by Lucas.
