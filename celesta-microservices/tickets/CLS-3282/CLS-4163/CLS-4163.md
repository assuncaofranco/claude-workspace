# CLS-4163 — Reward offering reasons (promotion)

**Feature:** per-brand gift reasons in promotion; gifts reference a reason by id.

## Setup
- Import `CLS-4163.postman_collection.json`; no environment file.
- Stack up: promotion, wallet, backoffice, mysql (`make init` after switching promotion to `CLS-4163`).
- Runner env (from the vault, never in the file): `guardKey`, `BO_oauth_client_id`, `BO_oauth_client_secret`, `BO_username`, `BO_password`.
- Run the whole collection in one go, in order; folders depend on earlier captures.

## Steps
1. Migration: four seeded reasons; pre-migration gift gone.
2. Create reason: valid, empty, blank, 64/65 chars, duplicates, other brand.
3. Delete reason: delete, delete again, other brand, unknown, recreate.
4. List reasons: brand scope, deleted included, limit, order on every field.
5. Offer gift: with/without/invalid `reasonId`, legacy `reason`, scenario.
6. Deleted reason on gifts: replay and gift list keep the name.
7. Current backoffice: offer with legacy `reason` still works.

Captured at runtime: `runTag` and the names derived from it, `reasonId`, `otherDomainReasonId`, `deletedReasonId`, `tmpReasonId`, `giftWithReasonId`, `replayGiftId`, `giftCount`, `BO_access_token`.
