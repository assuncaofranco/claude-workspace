# CLS-3471-CLS-3486: failed wallet call stored like PHP (PP1)

**Feature:** when the wallet rejects a bet, `game_transaction.errors` starts with the integer wallet code, as in PHP.

## Setup

- VPN on.
- Import the vault copy `~/.claude-secrets/postman/CLS-3471-CLS-3486.pp1-with-credentials.postman_collection.json` (this repo copy has no credentials). No environment.
- Order matters: folder 1, the browser step, then folder 2.

## Steps

1. Folder 1: player token, player id, launch SoftGamings game 41935.
2. Open `gameUrl` (printed in the Postman console, also in the variable) in a browser. Place one bet: the player has no balance, so the game answers insufficient funds.
3. Folder 2: BO token, player rounds since launch, round transactions. Each failed bet has `errors[0] === 3` and the PHP HTTP client message in `errors[1]`.

## Variables

| Variable | Example | What it is |
|---|---|---|
| `playerEmail` / `playerPassword` | vault | PP1 test player created for this ticket (282644, domain 56, DE) |
| `launchIp` | `87.32.0.1` | IP sent on launch; SoftGamings answers "Restricted country" for `127.0.0.1` |
| `gameId` | `41935` | 5 Lucky Lions, SoftGamings gateway 19 |
| `domainId` | `56` | player's domain |
| `BO_*`, `oauth_*` | vault | BO and Gateway OAuth clients |

Captured at runtime: `access_token`, `playerId`, `gameUrl`, `testFrom`, `BO_access_token`, `roundIds`, `testTo`.

## Notes

- PO-runnable. The bet is placed by a human in the game, because only the provider can call the webhook: the game session token never reaches the player.
- Game rounds come from BigQuery, so a fresh round can take a few minutes to show up in folder 2.
- Expected value, e.g. `[3, "HTTP/1.1 400 Bad Request returned for \"http://wallet-active/api/domain/56/wallet/<id>/game-transaction/all\"."]`. Before the fix it was `["wallet: http 400 (code=3)"]`.
- Errors raised by the game itself (e.g. `Bet amount is over maximum amount`) keep their text without a code, as in PHP.
- The BO OpenAPI documents `errors` as an array of strings; the first item is an integer (PHP did the same). Pre-existing, not changed here.
