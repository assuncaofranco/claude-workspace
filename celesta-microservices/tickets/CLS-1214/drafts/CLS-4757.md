# CLS-4757 — {F} [backoffice-front] Show every combined request ID on report payout lines

Sub-task: https://celesta.atlassian.net/browse/CLS-4757 · Parent: https://celesta.atlassian.net/browse/CLS-1214 · Repository: celesta-backoffice-front

## Overview

The transaction report (Finance) shows the withdrawal request a payout line paid in two places: the "WDR ID"
column of `TransactionReportListItem` and the "WDR ID" field of the side panel (`SidePanelInfoCards`). Both read
the line's single `withdrawRequestId` from `POST /api/gateway/domain/{domainId}/finance/transaction_reports` and
render `#<id>` as a link. The link resolves the request's status (`getWithdrawalRequest`) and opens the request on
the page that lists that status (`getWithdrawalRequestPath`).

Since CLS-1214, one payout can pay several requests, and sibling
[CLS-4756](https://celesta.atlassian.net/browse/CLS-4756) adds `withdrawRequestIds` to each report line. This
sub-task renders every ID of that list in both places, each linking to its own request, and stops reading
`withdrawRequestId` so that [CLS-4758](https://celesta.atlassian.net/browse/CLS-4758) can remove it from the
response.

## Architecture & Design

**Contract**, defined by sibling CLS-4756, on each element of the transaction report response:

| Line | `withdrawRequestId` (unchanged until CLS-4758) | `withdrawRequestIds` (new, `integer[] \| null`) |
|---|---|---|
| withdraw, combined payout | lead, e.g. `4290150` | `[4290150, 4292746, 4301966]` (ascending, lead included) |
| withdraw, single payout or synced before the change | `557795` | `[557795]` |
| withdraw with no request ID | `null` | `null` |
| any other type (`deposit*`, `refund`, `adjustment`) | `null` | `null` |
| statistics without the key (not deployed, rolled back) | as today | `null` |

A non-null list always has at least one ID. No request, filter, sort or count changes. This repository stops
reading `withdrawRequestId`. The field stays in the response until CLS-4758 removes it.

**One component for the row and the panel.** `WithdrawRequestLinks` (new, in
`src/components/page-components/transaction-report/`) renders a list of request IDs as `#<id>` links separated
by `", "`. The list cell and the side panel field both use it. A subcomponent shared within this folder follows
`TransactionReportActions`, which `TransactionReportListItem` and `TransactionReportTable` both use.

- The separator follows `promotionConfigurationIds` in
  `src/components/page-components/crm/players/player/sportsbook/PlayerBetListItem.sportsbook.js`: a
  `React.Fragment` keyed by the ID, with `", "` before every ID except the first.
- The link and its click are moved from today's code unchanged: celesta-ui `Link` with `as="button"`, which
  dispatches `getWithdrawalRequest(domainId, id, { onSuccess })`, then
  `router.push(getWithdrawalRequestPath(domainType, domainSlug, id, withdrawRequest.status))`.

**The caller handles the empty case.** `TableValue` shows its empty placeholder only when it has neither
children nor value, and `InfoCardField` marks the value `null-value` only when it is falsy. So the row and the
panel pass the component only when `withdrawRequestIds?.length` is truthy, and `null` otherwise. Lines with no
request keep today's rendering.

**No fallback to `withdrawRequestId`.** A `null` or missing `withdrawRequestIds` renders an empty WDR ID,
whatever `withdrawRequestId` holds.

**Order and count come from the response.** IDs are rendered in the order received, all of them: no sorting, no
cap, no ellipsis. The WDR ID column has no size modifier, so the cell widens rather than truncating.

**No text change.** The column header `transaction_report.column.wdr_id` and the side panel label
`transaction_report.additional_information.wdrId` stay as they are.

**No precedent in the code:** a list of links where each link resolves its target through a thunk before it
navigates. The existing lists of linked IDs (`PlayerBetListItem.sportsbook.js`, `AffiliationAndReferralTile.js`)
link with an `href`. Here, the withdrawal page to open depends on the request's status (`getWithdrawalRequestPath`),
and the report line does not carry that status. So each link keeps today's resolve-then-navigate click.

## Edge Cases & Error Handling

- **`withdrawRequestIds` is `null`**: no request, a non-payout type, or statistics without the key because
  CLS-4754 is not deployed or was rolled back. The cell and the field are empty, as today for a line with no
  request. During a statistics or backoffice rollback, payout lines show no WDR ID until the redeploy.
- **`withdrawRequestIds` is absent** (a backoffice older than CLS-4756): `?.length` is `undefined`, so the line
  is handled like `null`.
- **Empty array** (the contract says it never happens): treated like `null`.
- **One ID**: `#<id>` with no separator, the same link as today.
- **Many IDs** (a combined payout carries at most 10 requests, per CLS-4753): all are shown and the cell widens.
  There is no truncation, because the WDR ID column has no size modifier.
- **The request cannot be loaded on click**: unchanged from today. `getWithdrawalRequest` is called without
  `onError`, so nothing happens.
- **`withdrawRequestId` still present next to the list**: ignored.

## Acceptance criteria

From the parent: "In the transaction report, a combined payout shows the IDs of all the requests it paid", and
"a request that is the only validated request of the player … is paid in its own payout, as today", narrowed to
what this repository renders:

| Report line | WDR ID in the list row and in the side panel |
|---|---|
| `withdrawRequestIds: [4290150, 4292746, 4301966]` | `#4290150, #4292746, #4301966`, each opening its own request on the page of its status |
| `withdrawRequestIds: [557795]` | `#557795`, opening request 557795, as today |
| `withdrawRequestIds: null` (any `withdrawRequestId`) | the empty placeholder, no link |

- No file under `src/` reads `withdrawRequestId` from a report line.

## Decisions

- **When `withdrawRequestIds` is null or missing, fall back to `withdrawRequestId` while it exists?** No. Only
  `withdrawRequestIds` is read, so CLS-4758 has nothing left to remove in the front; a fallback would stay as dead
  code with no front sub-task to remove it. A rollback window shows an empty WDR ID until redeploy. Decided by Lucas.
- **Render the list in one shared component or inline in both places?** One `WithdrawRequestLinks` component in
  the transaction-report folder, used by the row and the side panel, so the click and the separator live in one
  place, as `TransactionReportActions` is shared today. Decided by Lucas.
- **Do any labels change ("update the translations")?** No text change. The header and the side panel label stay
  "WDR ID", one-request lines look as today, and the `", "` separator is hard-coded as in
  `PlayerBetListItem.sportsbook.js`. Decided by Lucas.
- **Delete the unreferenced key `transaction_report.column.withdrawRequestId`?** No: it is not a field read and
  is outside this sub-task. Decided by Lucas.
- **Deploy order?** Payment, then statistics, then wallet, then backoffice, then front. Decided by Lucas.
