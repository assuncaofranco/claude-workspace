# CLS-3676 money-path idempotency

**Feature:** a deposit delivered twice rewards each deposit_tier configuration once; claiming an already-claimed bonus answers 409.

## Setup
- Local only: promotion, wallet, segment, backoffice, gateway up; `localsqs` from `celesta-global-container`; nothing consuming `dev-promotion`.
- `python3 -I gen.py` regenerates the collection; `./run.sh` runs it (credentials from the vault at run time).
- Order matters: the script pushes the deposit jobs and runs promotion's consumer between the Newman parts.

## Steps
1. Folder 0: top up player 1 if EUR withdrawable is negative.
2. Folder 1 (BO): rc auto (claiming automatic) and rc direct; deposit_tier A and B, manual engagement by code, limit 6, tier 0-100, reward free_bonus -> rc auto.
3. Folder 2 (GW): player opts in to A and B by code.
4. Push tx1 success twice, consume 2. Folder 3: A and B each 1 rewarded, 1 engaged; 2 claimed bonuses.
5. Push tx2 success, consume 1. Folder 4: 2 rewarded each; 4 claimed.
6. Push tx3 initiated, pending, success, consume 3. Folder 5: 3 rewarded each; 6 claimed.
7. Push tx4 initiated, tx5 success, tx4 success, consume 3. Folder 6: 5 rewarded each; 10 claimed.
8. Folder 7: BO offers D and E from rc direct, cancels E; GW claims D (200); promotion direct claims D again (409); GW claims D again (404), E (404), unknown (404); BO sees one claimed.
9. Script prints the promotion events of A and B.

## Notes
- PO-runnable in preprod: folders 1, 2 and 7 except the DEV-ONLY promotion call. Folders 3-6 need the queue pushes, which only exist locally; in preprod the same deposit can only be redelivered by payment.
- Before the fix: folders 3-6 fail with exactly one extra reward per redelivery; the DEV-ONLY claim answers 404. After: 86 assertions, 0 failures (2026-10-27).
- The gateway turns every promotion 4xx except 403 into 404, so the player still sees 404 on a repeated claim; the 409 is on promotion's endpoint, which is what the money-path sheet checks.
- A deposit_tier pays the rewards hung on the tier aggregator, not the ones at configuration level: the setup posts the reward to `reward-aggregator/{id}/reward`.
- The first consume right after a push often returns empty on localsqs; `run.sh` consumes again until the queue is empty.
- No wallet read: wallet keys `sub_balance` by bonus id and promotion's ids restart after every `make init`, so local wallet rows mix runs.
- `playerPromotionLimit` counts rewarded promotions per player; 6 leaves room for the 5 rewards of the run.
- The other-player 404 (cell 19) is covered by the unknown-bonus id: the lookup filters by player, so a foreign id behaves like an unknown one. Player 29 has no wallet locally.
- The canceled-bonus claim id is assembled as `{rc}_{bonusId}` from BO captures: a canceled bonus is not listed on the GW side.
