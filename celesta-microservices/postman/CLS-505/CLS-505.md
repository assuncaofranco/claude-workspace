# CLS-505 — How to test (Symfony 7.4: game, promotion, contact, cms)

**Feature:** game (CLS-3288), promotion (CLS-3289), contact (CLS-3290) and cms (CLS-3291) on Symfony 7.4 and the `CLS-505` libraries, with no change in behaviour.

## Setup
- pp1/pp2: the PRs deployed. `PP=2 ./run-pp1.sh <service>` targets preprod-2 (same credentials, URL number changes). In pp2 domain 56 only has CGA games, so game folders 2 and 4 (Relax) do not run there. Run game, promotion, contact, cms in any order. The DEV-ONLY folder is skipped.
- Local: game, contact and cms on their branches, backoffice and gateway on master, `make init` in each. The global container (`localsqs`, `elasticsearch`) has to be up, and gateway master needs `make build` (PHP 8.5). Run `./run.sh <game|contact|cms>`.
- Game folder 1b (local only) tops up the fixture player, which starts with a negative balance.
- Edit `gen.py` and run `python3 gen.py` to regenerate the collections, rather than editing the JSON.

## Steps
1. game: GW launches the Relax game and reads the cashiertoken.
2. game: Relax bet 10, win 20, repeated bet gives 403, bet 15 then its rollback, net balance +10, rollback of an unknown tx is declined.
3. game: BO GET game, and an unknown id gives 404.
4. game: BO creates and offers a Relax free rounds reward, GW claims it (game grant), BO cancels it (game cancel).
5. contact: BO lists email providers, a PUT on an unknown id gives 404.
6. contact: GW forgot password, which reaches contact `/emails` through the queue.
7. cms: BO content tag create, list, patch, unknown id 404.
8. cms: BO content block create, get, put, patch, invalid status 400, inverted and half visibility period 400, unknown 404, delete.
9. cms: BO terms and conditions list, draft create and update, unknown 404 on update and publish.
10. cms: BO custom email template create, get, patch, unknown 404, delete.
11. cms (local only): render, bulk render and send called on cms directly, then publish the draft.
12. promotion: BO tags (duplicate 400, unknown 404), reward configuration manual and automatic with segment, list by segment, three promotion-side 400s, promotion configuration with tags, weekly schedule (empty and invalid days 400), tier aggregator, offer a free bonus, GW lists it, BO cancels, cleanup.

## Notes
- Everything except cms folder 5 and game folder 1b goes through BO, GW or a provider callback, so it runs in pp1.
- **Never publish terms and conditions in pp1.** Publishing locks every player of the domain until they sign. Folder 5 does it locally only. The draft created in pp1 has no delete route and stays in the list, named with `runTag`.
- Not checkable through an entry point, check by hand:
  - after the rollback, `game_transaction.related_transaction_id` is set on the BET_ROLLBACK row (local 2026-10-13 and pp1 2026-10-14: points to the original bet);
  - the email from forgot password and from cms send arrives (contact worker logs);
  - Evolution only checks `authToken` after it finds a live session, and the token is not readable in pp1. After the deploy, look in Datadog for Evolution callbacks with errors;
  - dd-trace 1.20: traces and logs of the three services still reach Datadog;
  - SQS workers consuming, and pod memory, per the specs' smoke lists.
