## Current State (what already exists)

- **Wallet** — `src/BonusBundle/EventListener/ORM/TurnToReal/TransactionWinWinningsListener.php`
  already implements winnings turn-to-real. It gates on `model === MODEL_WINNINGS` via `getModel()`
  — **not** on `getBonusModel()` — so promotion-system bonuses (`getBonusModel() === null`, with
  `model` populated from the Promotion claim payload) are handled correctly without any extra guard.
  Registered in `src/BonusBundle/Resources/config/services.yml` (doctrine `onFlush`/`postFlush`).
- **Promotion** — `RewardConfigurationConstants::MODEL_WINNINGS` exists and is in `MODELS`. The claim
  (`src/AppBundle/EventListener/ORM/BonusListener.php::postWalletBonusTransaction`) already sends
  `'model' => $rewardConfiguration->getModel()`. `AddWageringSubscriber` only adds/requires
  `wageringMultiplier` when `model === MODEL_WAGER`, so winnings already skips wager fields.
- **Status sync** — CLS-849 (`RewardAssetClaimedListener` in wallet → `BonusClaimedJob` →
  `BonusClaimedJobHandler` in promotion) syncs `played → claimed`. It does not gate on model.
- **Workflow** — `played → claimed` already exists: `BonusConstants::STATUS_TRANSITIONS` has
  `claimed.from = [offered, played]`. Confirmed.

> The flow already works end-to-end. CLS-1240 adds the OA schema fix and test coverage.

## Phase 1 — Promotion

- **OA schema fix**: `AddWageringSubscriber.php` — add `RewardConfigurationConstants::MODEL_WINNINGS`
  to the `non-wager model` enum. Currently only lists `upper`/`direct`; `winnings` is missing from
  the documented choices even though the runtime logic already handles it correctly.
- **Claim payload** (verify only): `postWalletBonusTransaction` sends `model` from
  `$rewardConfiguration->getModel()` and only adds `wageringMultiplier` when not null. No change needed.

---

## Phase 2 — Wallet

Two targeted changes to `TransactionWinWinningsListener`:

1. **`isWinningsBonusModel` — dual-path fallback**: use `getBonusModel()?->getModel() ?? getModel()`
   to make explicit that legacy bonuses use the `BonusModel` entity while promotion bonuses use the
   `model` string field set by `ClaimHandler` from the Promotion claim payload.
2. **Constant swap**: compare against `RewardConfigurationConstants::MODEL_WINNINGS` (Promotion namespace)
   instead of `BonusModelConstants::MODEL_WINNINGS` (Wallet namespace), which will be deleted when the
   migration to Promotion is complete.

No logic change — the runtime behaviour is identical. These are clarifying improvements that align the
code with the migration direction.

## Risks & Gotchas (carried from the CLS-851 / CEL-7576 work)

1. **Deploy order: wallet before promotion.** The claim contract is additive, but `ClaimType` has no
   `allow_extra_fields`; a new field sent by promotion to an old wallet is rejected. (Winnings adds no
   new claim field, so risk is low here — but keep the order.)
2. **Sibling-ticket merge conflicts (CLS-1058 style).** When merging `master`, expect possible
   conflicts in `BonusListener.php` if another ticket touched the claim payload. Resolve keeping the
   correct version and re-check with `git diff origin/master`.
3. **`commit-msg` hook rejects the `CLS` prefix.** Allowed: `V2|CEXT|CEL|CELM|CELB|CELC|CELD|CTB|CSB|hotfix`.
   `CLS-1240` will be declined. Align with the team to add `CLS` to the hook regex, or use the matching
   CEL ticket. Do **not** use `--no-verify` without explicit approval.
4. **`pre-commit` runs phpinsights** on `origin/master...branch` PHP files (excluding `tests/`). Files
   pulled in by a master merge can be linted and block the commit — fix style, don't skip the hook.
5. **Constants/jobs live in shared libs** — `celesta-constants` / `celesta-job-library`. `MODEL_WINNINGS`
   already exists, so no new constant is expected. If one is needed, stop and create it in the lib first.
6. **`wager_progress_percent` is computed, not stored for bonuses** (mapped as `#[ORM\Column]` only on
   `CashSubBalance`, not `BonusSubBalance`). Irrelevant to winnings, but don't be surprised by null in DB.
7. **Commit messages**: no AI / "Co-authored-by" references.
